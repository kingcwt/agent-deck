# Active Memory

## Description

把最近一轮已经完成的用户-助手对话写入当前项目的 `active-memory.md`，形成一条结构化记忆。

## Parameters

- 必填：无。
- 来源范围：当前快捷调用之前最近一轮已经完成的用户-助手对话。
- 输出文件：项目根目录下的 `active-memory.md`。
- 可选参数：无。

## Shortcuts And Commands

- Codex 快捷键：`$kc-am`
- Codex 完整命令：`$kc-am`
- Claude Code 快捷键：`/kc-am`
- Claude Code 完整命令：`/kc-am`

## Examples

### Codex

```text
$kc-am
```

### Claude Code

```text
/kc-am
```

## Workflow

### 1. 先定位记忆文件

- 把 `/kc-am` 和 `$kc-am` 视为这个工作流的显式快捷触发词。
- 先解析当前项目根目录。
- 使用项目根目录下的 `active-memory.md` 作为唯一记忆文件。
- 如果 `active-memory.md` 不存在，就在项目根目录创建它。
- 如果文件已存在，先读取足够内容以确定下一个序号，再进行追加。

### 2. 选择要整理的源对话

- 使用当前快捷指令之前，最近一轮已经完成的用户与助手对话作为整理对象。
- `原始问题` 必须尽量保留用户原始提问，只允许去掉像当前快捷指令这类明显外围噪音。
- `问题` 字段必须是对用户真实问题或意图的简短整理版。
- `描述` 字段必须把助手回复整理成结构清晰、便于扫读的内容。
- 如果没有明确可整理的上一轮对话，就直接说明并停止，不能编造。

### 3. 构造一条结构化记忆

- 每次调用只写入一条记录。
- 时间使用实际写入时的本地当前时间。
- 根据 `active-memory.md` 现有内容，按 `1`、`2`、`3` 这样的顺序递增编号。
- 严格使用这套 markdown 结构和字段顺序：

```md
## 时间：YYYY-MM-DD HH:mm:ss

> 原始问题：...

## N. ...

## 描述：

1. ...

2. ...

3. ...
```

- 时间这一行必须使用 `## `，按 H2 渲染。
- 原始问题这一行必须使用 `> `，按引用块渲染。
- 整理后的问题这一行必须使用 `## `，内容只保留 `N. 问题标题`。
- 最终写入内容里不要再出现 `序号 问题：` 这四个字。
- `描述：` 这一行必须使用 `## `，按 H2 渲染。
- 描述下面的每一条都必须使用普通编号列表，例如 `1. ...`，不要添加 `### ` 这类标题标记。
- 整理后的 `问题` 要短、聚焦。
- `描述` 必须拆成清晰的编号点，不要写成一整段。
- 如果回复中包含关键技术名词、命令、文件名、决策、约束或后续动作，要保留下来。
- 不要添加无意义的套话。

### 4. 安全追加

- 如果文件为空，直接写入这条记录。
- 如果文件已有内容，必须先追加一行单独的 `-----` 分割线，再空一行，然后再写入新条目。
- 分割线必须独占一行，避免前后两条记录视觉上粘在一起。
- 除非用户明确要求，否则不要改写、重排或清理旧记录。
- 不要额外创建别的记忆文件，也不要更换这个标准文件位置。

### 5. 报告结果

- 报告实际写入的是哪个文件。
- 报告使用了哪个序号。
- 报告记录下来的整理后问题标题。
- 如果写入失败，直接说明具体阻塞错误。

## Guardrails

- 这是一个记录项目记忆的工作流，不是重新回答新问题的工作流。
- 除非用户明确要求，否则不要把当前这次快捷指令本身当成要整理的对话内容。
- 不要编造缺失的用户意图或助手结论。
- 不要跳过文件存在性检查，也不要跳过序号检查。
- 记忆条目要保持简短、结构化，并且方便后续检索。
